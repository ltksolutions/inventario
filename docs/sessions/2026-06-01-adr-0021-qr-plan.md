## Tri dizajnové rozhodnutia z Opus session (záväzné pre implementáciu)

Tieto boli odsúhlasené s Janikom — nemeniť bez konzultácie:

**Rozhodnutie A — `inventoryNumber` regex.** Uvoľnený na `/^[A-Z]{1,5}-(\d{4}-)?\d{3,8}$/`
— povoľuje dva tvary: `PREFIX-ROK-PORADIE` (includeYear=true) aj `PREFIX-PORADIE`
(includeYear=false). Poradie 3–8 cifier. Regex je len záchranná sieť; server je jediný
generátor. **HOTOVÉ v K1.**

**Rozhodnutie B — prefix je čisto tenant-level.** `inventoryNumberFormat.prefix` na
`Organisation` je **jediný** zdroj prefixu. Žiadny per-request override. Dôvod: solo
nasadenie per tenant, jeden kód stačí. **Dopad na K2:** `assets.service.ts create()` už
NEBUDE brať `inventoryNumberPrefix` z requestu — vyčíta celý formát z tenant configu.
Treba upraviť aj routes (prestane požadovať prefix v body) a frontend formulár.

**Rozhodnutie C — `foundContactInfo` soft guidance.** Voľný objekt {email?, phone?, message?}

- GDPR-aware `.describe()` komentáre navádzajúce na organizačný (nie osobný) kontakt.
  Žiadna tvrdá validácia. **HOTOVÉ v K1** (vrátane UI hint, ktorý treba zobraziť v settings — K5).

  (bool default false), `foundContactInfo` (nullable), `inventoryNumberFormat` (nullable)

## K2 — `publicToken` generácia + refaktor inventoryNumber + migrácia

**Súbory:** `apps/api/src/modules/assets/assets.service.ts`, `assets.repository.ts`,
`assets.routes.ts`, nová migrácia v `apps/api/src/migrations/`.

1. **`publicToken` generácia v `create()` transakcii** (vedľa inventoryNumber, Step 1):
   - Použiť `crypto.randomBytes(20)` + `base32Encode` z `apps/api/src/lib/base32.ts`
     (žiadny nový dependency; base32 je URL-safe, ~32 znakov → sedí do min16/max64).
   - Generovať VŽDY (nezávisle od `publicAssetLookup`).
   - Unique index na `publicToken` (globálne unique stačí — token je CSPRNG).
     Pridať do repo `ensureIndexes()` (pozri ako to robí existujúci kód pre inventoryNumber).
2. **Refaktor inventoryNumber generácie (rozhodnutie B):**
   - `create()` prestane brať `inventoryNumberPrefix` z `CreateAssetServiceInput`.
   - Namiesto toho načíta `organisation.inventoryNumberFormat` (cez organisations repo
     alebo tenant context) a poskladá číslo podľa `{ prefix, padding, includeYear, resetYearly }`:
     - includeYear=true: `${prefix}-${year}-${seq.padStart(padding,'0')}`
     - includeYear=false: `${prefix}-${seq.padStart(padding,'0')}`
   - `findHighestInventorySequence` — ak resetYearly=false, hľadať max naprieč všetkými
     rokmi (nie len aktuálny rok). Pozri súčasnú implementáciu v repo.
   - Ak tenant nemá `inventoryNumberFormat` (null) → vhodiť jasný BadRequestError
     („Organizácia nemá nastavený formát inventárneho čísla").
   - Upraviť `assets.routes.ts` — POST body prestane požadovať prefix.
3. **Migrácia** `apps/api/src/migrations/2026-06-01-asset-public-token.ts`:
   - Dogenerovať `publicToken` všetkým existujúcim assetom (ktoré ho nemajú).
   - Pozri existujúce migrácie pre vzor (runner ich púšťa pri štarte cez `runPendingMigrations`).
   - **Pozor na Mongo sparse/partial index** — ak by niektoré assety mali publicToken null
     pred migráciou, použiť `partialFilterExpression: { publicToken: { $type: 'string' } }`
     namiesto sparse (pozri memory — sparse indexuje explicit null).

## K3 — QR render endpoint

**Súbor:** `apps/api/src/modules/assets/assets.routes.ts` (+ prípadne malý lib helper).

- `GET /v1/assets/:id/qr?format=svg|png` — auth, EMPLOYEE+ (rovnaký RBAC ako GET detail).
- QR knižnica: použiť `qrcode` npm (pridať do `apps/api` deps). SVG aj PNG vie.
- Obsah QR = `${organisation.appBaseUrl}/scan/${asset.publicToken}`.
  - Doménu brať **VÝLUČNE z `organisation.appBaseUrl`** — NIKDY z `request.headers.host`
    (ADR rozhodnutie 6, host-header injection).
  - Ak `appBaseUrl` je null → 409/400 s jasnou správou („Nastavte appBaseUrl pre QR kódy“).
- Content-Type podľa formátu (`image/svg+xml` / `image/png`), cacheable header (QR je stabilné).

## K4 — verejný lost & found endpoint

**Súbory:** nový `apps/api/src/modules/assets/public-assets.routes.ts` (alebo v assets.routes
s explicitným non-auth segmentom), registrácia v `server.ts`.

- `GET /public/scan/:publicToken` — **bez auth**, rate-limited.
  - POZOR na registráciu: musí byť mimo `requireAuth` middleware. Pozri ako sú registrované
    verejné routes (health, prípadne invitation preview) — nasledovať ten vzor.
  - `@fastify/rate-limit` je už dependency. Nastaviť lokálny rate-limit na túto route
    (napr. 30/min/IP) — pozri existujúce rate-limit configy (auth routes: 10/15min).
- Logika:
  1. Nájsť asset podľa `publicToken` (nový repo metóda `findByPublicToken` — pozor,
     toto je cross-tenant lookup podľa globálneho tokenu, NIE organisation-scoped).
  2. Načítať jeho `organisation`.
  3. Ak `organisation.publicAssetLookup === false` → **404** (NIE 403 — nepotvrdzuj existenciu).
  4. Ak true → vrátiť `PublicAssetView` cez **explicitný mapper** (pole po poli, NIE spread):
     ```ts
     {
       (organisationName,
         organisationLogoUrl,
         inventoryNumber,
         name,
         foundContact);
     }
     ```
  5. Asset nenájdený → tiež 404.

## K5 — frontend

**Súbory:** `apps/web/src/app/scan/[publicToken]/page.tsx` (nová route),
úprava detailu assetu (`apps/web/src/app/assets/[id]/page.tsx` alebo komponent),
settings organizácie (`apps/web/src/app/settings/organisation/page.tsx`).

1. **`/scan/[publicToken]`** — redirect logika (ADR flow diagram):
   - prihlásený → redirect na `/assets/{id}` (treba resolve id z tokenu — buď public
     endpoint vráti aj id pre auth usera, alebo samostatný resolve; rozhodnúť pri impl).
   - neprihlásený + `publicAssetLookup` ON → zobraz found-it view (volá `/public/scan/:token`).
   - neprihlásený + OFF → redirect na `/login?redirect=/scan/{token}`.
2. **QR na detaile assetu** — zobraziť QR (img src = `/v1/assets/:id/qr?format=svg`),
   tlačidlo „Stiahnuť QR" / „Tlačiť štítok".
3. **Settings organizácie** — formuláre pre `appBaseUrl`, `publicAssetLookup` (toggle),
   `foundContactInfo` (s **GDPR hint textom** o organizačnom kontakte — rozhodnutie C),
   `inventoryNumberFormat` (prefix, padding, includeYear, resetYearly).

## K7 — regenerácia artefaktov + testy (POVINNÉ pred commitom)

Toto je lekcia z dnešného CI (104/105) — po zmene schém/routes treba:

```
pnpm --filter @inventario/shared-types test        # unit fixtures
pnpm test                                           # plný beh (nie scoped!)
pnpm --filter @inventario/api openapi:export:offline   # regen openapi.json (BEZ --check, cez MongoMemoryServer)
pnpm typecheck
```

> **NIKDY** `openapi:export` bez `:offline` na regen — ide na reálny Atlas a zlyhá na bad auth.
> `:offline` použije MongoMemoryServer. Regen je beh kódu → spúšťa Janika, nie cez MCP.

Po novom POST flow (bez prefixu v body) skontrolovať aj existujúce asset integračné testy
v `apps/api/tests/` — môžu posielať `inventoryNumberPrefix` a bude treba ich upraviť na
tenant-config based flow (vytvoriť org s `inventoryNumberFormat` v setupe).

## Kontext: kde čo žije

- Token gen: `apps/api/src/lib/base32.ts` (base32Encode) + Node `crypto.randomBytes`
- inventoryNumber gen dnes: `assets.service.ts` `create()` Step 1 (hardcoded `padStart(3)`)
- RBAC vzor: GET=EMPLOYEE+, POST/PATCH=ASSET_MANAGER+ADMIN, DELETE=ADMIN
- Rate-limit vzor: auth routes (10/15min), invitation (20/15min)
- Verejná route vzor: pozri health.routes.ts / invitation preview (410 bez auth)
- Migrácie: `apps/api/src/migrations/` + runner `runPendingMigrations` v buildServer
- Mongo index pozn.: partialFilterExpression `{ $type: 'string' }` nie sparse (memory)
