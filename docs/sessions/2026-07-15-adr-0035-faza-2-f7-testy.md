## F7a — vitest infra pre apps/web + middleware.ts testy

Nový `apps/web/vitest.config.ts` (`environment: 'node'` — middleware
nepotrebuje DOM; poznámka v komentári, ako prepnúť na `jsdom` pre budúce
component testy). `apps/web/package.json`: doplnená `vitest` devDependency

- `test`/`test:watch` skripty (nahradili placeholder).

Nový `apps/web/tests/unit/middleware.test.ts` — volá `middleware()`
priamo s ručne zostaveným `NextRequest` (žiadny dev server), `fetch`
mockovaný cez `vi.stubGlobal`. 9 testov: kanonický host passthrough bez
fetch volania, `.vercel.app` suffix passthrough, neregistrovaná doména
→ 404, sieťová chyba → fail closed 404, rewrite na `/tenant-login` pre
`/` aj `/tenant-login` (s `?domain=`), redirect 307 na
`app.inventario.estate` pre inú cestu (vrátane query stringu), 60s cache
(druhé volanie nevyžaduje nový fetch).

Overené empiricky v sandboxe (mimo vitest, priamym Node volaním), ako
presne vyzerajú `NextResponse.rewrite()`/`redirect()`/`next()` hlavičky
(`x-middleware-rewrite`, `location`, `x-middleware-next`), aby asserty
v teste sedeli na skutočné API, nie na predpoklad.

**Známy limit:** `vitest` nie je nainštalovaný v sandboxe (nová
devDependency, žiadny `pnpm install` v sandboxe — zakázané). `tsc
--noEmit` na `apps/web` preto zlyhá na `Cannot find module 'vitest'`,
kým Janika nespustí `pnpm install` lokálne. `eslint`/`prettier` na nových
súboroch prešli čisto (nezávisia od modulovej rezolúcie typov).

## F7b — end-to-end CORS testy cez app.inject

Rozšírený `apps/api/tests/integration/dynamic-cors.test.ts` (predtým
testoval len `createDynamicCorsOrigin()` priamo) o nový describe blok
`end-to-end cez app.inject` — reálny HTTP request s `Origin` hlavičkou
proti `GET /v1/public/organisations/login-context`, cez skutočnú
`@fastify/cors` registráciu v `server.ts`:

- registrovaná vlastná doména → `Access-Control-Allow-Origin` +
  `Access-Control-Allow-Credentials: true`.
- neregistrovaná doména → hlavička chýba.
- statický `CORS_ORIGINS` zoznam (`http://localhost:3001` default)
  funguje nezmenene popri dynamickom resolveri.
- preflight `OPTIONS` request pre registrovanú doménu prejde s
  korektnými hlavičkami.
